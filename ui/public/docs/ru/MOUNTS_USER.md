# Сетевые шары

Сетевая шара — папка на удалённом сервере (NAS, файловый сервер, рабочая станция), которую LiveQX подключает к серверу как локальную. Из неё каналы могут брать контент в режиме [источника контента из папки](CONTENT_SOURCE_USER.md) и добавлять файлы в [плейлист](PLAYLIST_USER.md).

Раздел: **Настройки → Хранилища**. Доступен **только администратору**.

Подключённые шары видны на сервере в каталоге `/mnt/liveqx/`. Подключение оформляется как системные точки монтирования и **сохраняется после перезагрузки сервера**.

## Список

В таблице для каждой шары:

- **Точка монтирования** — путь на сервере, например `/mnt/liveqx/media`;
- **Тип** — `cifs` или `nfs`;
- **Источник** — адрес шары на удалённом сервере;
- **Состояние** — Активен, Запускается…, Неактивен, Ошибка или Неизвестно;
- **Учётные данные** — для CIFS: имя пользователя (звёздочка означает, что пароль сохранён) или `guest`;
- **Обновлено** — когда состояние проверялось в последний раз.

В строке доступны **Проверить**, **Обновить статус**, **Изменить** и **Удалить**.

## Типы

### CIFS (SMB, «Windows-шара»)

Протокол общего доступа Windows и Samba. Источник: `//192.168.1.10/share` или `//nas.local/media`. Для подключения нужны **имя пользователя** и пароль, при необходимости **домен**, либо режим `guest` (без пароля).

### NFS

Протокол Linux/Unix и корпоративных хранилищ. Источник: `192.168.1.10:/srv/share`. Учётные данные не нужны, доступ разрешается по IP-адресу на стороне хранилища.

## Добавление

1. **Новый mount** в правом верхнем углу.
2. Заполните:
   - **Файловая система** — CIFS или NFS.
   - **Источник** — адрес шары (см. выше).
   - **Точка монтирования** — путь внутри `/mnt/liveqx/`, например `/mnt/liveqx/media`. Папка создаётся автоматически.
   - **Параметры монтирования** — необязательно; через запятую, без `ro` (для этого есть переключатель). Подсказки: для CIFS `vers=3.0,iocharset=utf8`, для NFS `vers=4.1`.
   - **Только чтение** — рекомендуется держать включённым, если каналы только читают контент: так файлы нельзя случайно изменить или удалить.
   - Для CIFS: **Пользователь**, **Пароль**, **Домен** либо `guest`.
3. Нажмите **Проверить** — сервер попробует подключить ресурс и сообщит, доступен ли он (или причину, почему нет).
4. Сохраните. Источник и точка монтирования обязательны; для CIFS нужно указать пользователя.

После сохранения статус сменится на «Активен» или «Ошибка» с описанием.

## Использование в каналах

Как только шара подключена, её содержимое доступно по пути `/mnt/liveqx/…`. Этот путь указывается:

- в настройках **Источник контента** канала (папка для режимов «Кэш» или «Passthrough»);
- при добавлении файла или папки в плейлист вручную.

Одну и ту же шару могут использовать несколько каналов.

## Изменение

**Изменить** открывает ту же форму. Чтобы оставить прежний пароль CIFS, оставьте поле пароля пустым. Сам пароль в интерфейсе не показывается.

## Удаление

**Удалить** отмонтирует шару и удалит запись. Файлы на самом удалённом сервере не затрагиваются. Каналы, которые брали контент из этой шары, потеряют доступ к новым файлам; кэшированные файлы (режим «Кэш») продолжат играть.

## Состояние и диагностика

- **Обновить статус** заново запрашивает состояние шары у системы.
- Если статус «Ошибка», проверьте адрес и учётные данные, доступность удалённого сервера по сети, версию протокола в параметрах (`vers=…`).
- Для проверки того, что канал видит файлы, откройте вкладку канала **Наблюдатель** — см. [Источник контента](CONTENT_SOURCE_USER.md).

## Безопасность

- Пароль CIFS хранится в базе LiveQX в зашифрованном виде (ключом Master Key). Для самого подключения служба монтирования временно записывает его в защищённый файл в оперативной памяти (`/run/liveqx/creds/`, доступ только у root), который исчезает при перезагрузке. В интерфейсе пароль никогда не показывается.
- Режим «Только чтение» защищает файлы на шаре от случайных изменений.
