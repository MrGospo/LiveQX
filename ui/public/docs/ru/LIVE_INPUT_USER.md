# Live-источники

Live-источник — это запись плейлиста, которая берёт **готовый внешний поток** (камеру, OBS, другой сервер) и показывает его в эфире заданное время. Остальные записи плейлиста — файлы и фотографии — продолжают играть как обычно.

Подходит, например, для:

- вставки прямого включения с камеры в ролики;
- ретрансляции потока с другого сервера в заданное время;
- эфира из OBS или студийного оборудования.

## Чем отличается от файла

| | Файл или фото | Live-источник |
|---|---|---|
| Что играет | Заранее подготовленный контент | Поток снаружи в реальном времени |
| Сколько в эфире | Длительность файла или фото | Задаётся в записи: **длительность** |
| Если источник пропал | — | Канал показывает запасной кадр и ждёт возвращения |

Это **не режим всего канала**, а обычная запись плейлиста: её можно поставить между файлами и перемещать так же, как они.

## Добавление

Страница канала → вкладка **Плейлист** → **Добавить live-источник**. Заполните:

- **Тип** — RTMP, RTSP, Multicast или NDI.
- **ID** — уникальное в плейлисте имя записи (обязательно).
- **URL** — адрес потока (для NDI вместо URL указывается **имя NDI-источника**).
- **Длительность** — сколько секунд эта запись остаётся в эфире.

После добавления запись можно изменить кнопкой **Редактировать**: там же задаются **прогрев** и **порог потери сигнала**.

Добавлять записи может оператор (на канале с правом «Управление») и администратор. Если канал использует источник контента из папки, плейлист ведётся автоматически, и ручные записи добавить нельзя — см. [Источник контента](CONTENT_SOURCE_USER.md).

## Поддерживаемые типы

- **RTMP** — приём потока с RTMP-сервера по адресу `rtmp://сервер/приложение/ключ`. LiveQX подключается к источнику сам (режим клиента). Ключ потока в диагностике скрывается.
- **RTSP** — IP-камеры и RTSP-серверы: `rtsp://логин:пароль@192.168.1.10:554/stream1`. По умолчанию используется TCP.
- **Multicast** — приём потока из группы: `udp://239.1.2.3:1234`.
- **NDI** — источник по имени в локальной сети; нужна библиотека NDI на сервере.

## Прогрев, потеря сигнала и длительность

- **Прогрев** (по умолчанию 5 секунд) — за столько секунд до начала записи LiveQX заранее открывает источник, чтобы медленное подключение или вступление в группу multicast не задерживало эфир.
- **Порог потери сигнала** (по умолчанию 2 секунды) — если от источника нет данных дольше этого времени, запись считается потерянной.
- **Длительность** — запись завершается ровно по истечении заданного времени, даже если источник ещё вещает. Это сохраняет точность эфира.

## Что происходит, если источник пропал

Пока источник недоступен (до начала записи, при прогреве, при потере сигнала), вместо него показывается **запасной кадр**. По умолчанию это заглушка канала (**Конфигурация → Заглушка**); если заглушка не задана, показывается чёрный кадр. Источник при этом продолжает переподключаться сам, и когда поток вернётся, запись автоматически снова покажет его.

## Безопасность адреса

Если в URL указаны логин и пароль (`rtsp://user:pass@…`), эти данные видны всем, кто может редактировать плейлист канала. Поэтому лучше создавать для камеры отдельную учётную запись с минимальными правами, а доступ ограничивать по IP или через VPN.

## Что можно сделать иначе

Если нужно пересылать поток UDP/multicast «как есть» без вставки в плейлист, используйте раздел **Шлюз** (администратор).
