# Добавление выхода

Как добавить выход на канал. Поля зависят от типа, общая последовательность одна.

> Сначала прочтите [Выходы — общее](OUTPUTS_OVERVIEW.md), чтобы выбрать нужный тип.

## Кто может

Добавлять, изменять, перезапускать и удалять выходы могут оператор (на каналах с правом «Управление») и администратор.

## Общая последовательность

1. Страница канала → вкладка **Выходы**.
2. **Добавить выход**.
3. Выберите **тип**: SRT, MULTICAST, RTMP или HLS.
4. Задайте **ID выхода** — латиница, цифры, `_` и `-`, до 64 символов. Он уникален в пределах канала и не меняется.
5. Заполните поля типа (см. ниже).
6. При необходимости измените **лимит очереди (МБ)** — по умолчанию 4.
7. Нажмите **Добавить**.

Если канал уже работает, выход запускается сразу. Если остановлен — запустится вместе с каналом.

Тип выхода после создания изменить нельзя — нужно удалить выход и создать новый.

## Общие поля

- **Включён** — выключенный выход остаётся в конфигурации, но поток не отдаёт.
- **Сетевой интерфейс источника** (SRT, Multicast, RTMP) — через какую сетевую карту отправлять трафик. «По умолчанию» — маршрут выбирает система. Полезно на серверах с несколькими сетевыми картами.

## SRT

- **Адрес** — подставляется `0.0.0.0`.
- **Порт** — порт, на котором LiveQX ждёт подключения (в форме по умолчанию 4000).

Проверка: в VLC «Открыть сетевой поток» → `srt://адрес-сервера:порт`.

SRT-выход обслуживает одного зрителя за раз.

## Multicast

- **Адрес** — группа multicast из диапазона 224.0.0.0–239.255.255.255. В частных сетях обычно берут `239.x.x.x`.
- **Порт** — UDP-порт от 1 до 65535.
- **TTL** — через сколько маршрутизаторов проходит поток (1–255, по умолчанию 16): `1` — только локальная подсеть, `16` — корпоративная сеть, `255` — без ограничений.

Параметры MPEG-TS (Service ID, TSID и др.) задаются на вкладке **Конфигурация** канала в блоке **MPEG-TS / IPTV**. Если несколько каналов вещают в одну подсеть, у каждого должен быть свой **Service ID**.

Для multicast используйте постоянный битрейт (CBR) в кодировании канала.

Проверка: VLC → `udp://@239.x.x.x:порт`.

## RTMP

- **URL** — полный адрес приёма вместе с ключом потока, например `rtmp://a.rtmp.youtube.com/live2/xxxx-xxxx-xxxx` или `rtmps://…`. Должен начинаться с `rtmp://` или `rtmps://`.

Отдельного поля для ключа нет: ключ входит в URL. **Не показывайте этот URL посторонним** — по нему можно вещать на ваш канал.

URL и ключ берутся в личном кабинете платформы (YouTube Студия → Трансляция; VK Видео → настройки трансляции; Twitch → панель автора).

Проверка: запустите канал и через 10–30 секунд откройте страницу трансляции на платформе.

## HLS

- **Каталог** — абсолютный путь к каталогу на сервере, куда писать файлы. Каталог должен существовать, и у службы LiveQX должно быть право записи (выбрать его можно кнопкой обзора, она доступна администратору).

LiveQX записывает в каталог плейлист `stream.m3u8` и сегменты `seg_00000.ts` и так далее (сегмент 6 секунд, в плейлисте 5 сегментов, старые удаляются). **Раздавать** эти файлы зрителям должен ваш веб-сервер (nginx и т. п.) или CDN — сам LiveQX HLS по HTTP не отдаёт.

Проверка: убедитесь, что в каталоге появляются новые файлы, и откройте адрес `stream.m3u8` на вашем веб-сервере в Safari или VLC.

## NDI

В форме веб-интерфейса типа NDI нет. Сервер выход NDI поддерживает: его можно добавить через REST API (`POST /api/channels/{id}/outputs`) с параметрами `type: "ndi"` и `ndi_name` (имя источника для NDI-приёмников), либо указать в файле конфигурации канала. Для работы нужна библиотека NDI на сервере.

## Изменение и удаление

В строке выхода на вкладке **Выходы**:

- **Изменить** — открывает ту же форму. При сохранении выход **пересоздаётся**: поток на этом выходе прерывается на секунды. Если новые параметры некорректны и выход не удалось собрать заново, выход пропадёт, и его придётся добавить заново.
- **Перезапустить** — переподнимает выход без изменения настроек.
- **Удалить** — выход останавливается и удаляется, действие необратимо.

## Проверка работоспособности

После запуска канала на вкладке **Выходы** выход должен показать состояние «подключён», а счётчики отправленных байтов должны расти. Если это не так, см. [Типичные проблемы](TROUBLESHOOTING.md).
