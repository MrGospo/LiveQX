# Мастер-ключ

Раздел: **Настройки → Мастер-ключ**. Доступен **только администратору**.

Мастер-ключ — это ключ, которым LiveQX шифрует сохранённые секреты:

- пароли LDAP и SMTP;
- пароли сетевых шар (CIFS);
- секрет, которым подписываются сессии пользователей;
- подпись журнала действий (по ней видно, что записи журнала не подделаны).

Пароли пользователей этим ключом **не шифруются**: они хранятся в виде необратимых отпечатков.

Если ключ украден вместе с данными, шифрование ничего не защищает. Если ключ потерян, сохранённые секреты прочитать нельзя. Поэтому важно, **где** он лежит и **как** сохранён.

## Где может лежать ключ

| Способ | Что это | Когда выбирать |
|---|---|---|
| **Файл вне каталога данных** | `/etc/liveqx/master.key`, владелец `root`, группа `liveqx`, права `0640`. Выбирается установщиком по умолчанию | Обычная установка. Копия каталога данных (резервная копия, снимок виртуальной машины) ключ с собой не уносит |
| **Учётные данные systemd** | Ключ зашифрован средствами systemd и привязан к этому серверу, а при наличии модуля TPM2 — и к нему | Сервер с TPM2: даже копия всего диска не откроет ключ на другой машине |
| **Парольная фраза** | Файл ключа зашифрован фразой, которую вводит администратор | Нужна защита даже от кражи всего сервера, и администратор готов вводить фразу после каждого запуска |

Страница **Мастер-ключ** показывает, как хранится ключ сейчас. Если ключ лежит **в каталоге данных** (так было в старых установках), вверху появится предупреждение: любая копия каталога унесёт ключ вместе с данными, и шифрование перестаёт помогать.

Без модуля TPM2 учётные данные systemd защищают от копии каталога `/etc` и каталога данных, но **не** от копии всего диска: секрет сервера лежит на том же диске.

## Выбор при установке

```
sudo ./packaging/install.sh --master-key-store=file         # по умолчанию
sudo ./packaging/install.sh --master-key-store=creds        # учётные данные systemd
sudo ./packaging/install.sh --master-key-store=passphrase   # парольная фраза
```

Для `creds` нужен systemd версии 250 или новее. Для `passphrase` установщик спросит фразу в терминале.

## Старая установка: вынести ключ из каталога данных

Ключ переезжает **без перешифровки**: те же 32 байта просто сохраняются в другом месте.

```
sudo ./packaging/install.sh migrate-master-key
```

Команда остановит службу, перенесёт ключ в `/etc/liveqx/master.key`, запустит службу и, только убедившись, что она работает, удалит старый файл. При неудаче всё возвращается как было.

Старые резервные копии каталога данных по-прежнему содержат **прежний** ключ. Чтобы сделать их бесполезными, после переноса смените ключ (см. «Ротация»).

## Парольная фраза

Включить защиту фразой (служба должна быть остановлена):

```
sudo systemctl stop liveqx
sudo liveqx --config /etc/liveqx/config.json --protect-master-key
sudo systemctl start liveqx
```

Фраза спрашивается дважды, не короче **12 символов**, на экране не показывается. Сам ключ данных не меняется, поэтому ничего перешифровывать не нужно.

Остальные команды:

| Команда | Что делает |
|---|---|
| `--change-master-passphrase` | Меняет фразу (спросит старую и новую) |
| `--unprotect-master-key` | Снимает защиту фразой |

Для сценариев, где терминала нет, добавьте `--passphrase-stdin`: фразы читаются из стандартного ввода, по одной в строке на каждый вопрос.

### Что происходит при запуске

Служба с защитой фразой стартует **запечатанной**: она запущена, но открывает только страницу «Служба запечатана». Откройте обычный адрес LiveQX в браузере и введите фразу. После этого служба запускается как обычно на том же адресе.

Если страница недоступна (порт занят, не поднялся TLS), фразу можно ввести прямо на сервере, без сети:

```
sudo liveqx --config /etc/liveqx/config.json --unseal
```

Команда соединяется с закрытым сокетом `unseal.sock` в каталоге состояния (доступ только у пользователя службы и root), спрашивает фразу без показа на экране и действует по тем же правилам защиты от подбора. Когда служба уже запущена, команда сообщит, что запечатывать нечего.

**Важно:** пока фраза не введена, не работает ничего: каналы не загружаются, эфир не идёт. После перезагрузки или сбоя питания эфир не поднимется сам, пока кто-то не введёт фразу. Если сервер должен возвращаться в эфир без вмешательства, выбирайте файл или учётные данные systemd.

Защита от подбора: после нескольких неверных попыток с одного адреса ввод приостанавливается, и паузы удлиняются до 5 минут. В это время даже верная фраза не принимается.

## Ротация (смена ключа)

Ротация создаёт **новый** ключ и перешифровывает им все секреты. Службу нужно остановить:

```
sudo systemctl stop liveqx
sudo liveqx --config /etc/liveqx/config.json --rotate-master-key
sudo systemctl start liveqx
```

Старый ключ остаётся рядом файлом `master.key.bak.<время>` — храните или удалите его осознанно. Если хотя бы один секрет не расшифровывается старым ключом, ротация отказывается работать и **ничего не меняет**.

Если ключ защищён фразой, она будет запрошена, а новый ключ получит ту же фразу.

**Ключ в учётных данных systemd** (`master_key_store` равен `creds`) ротируется той же командой. LiveQX расшифровывает текущие учётные данные, создаёт новый ключ, шифрует его средствами `systemd-creds` (с привязкой к TPM2, если он есть) в соседний файл, перешифровывает секреты и только потом подменяет файл. Старые учётные данные остаются рядом файлом `liveqx_master_key.bak.<время>`.

Ротация не применяется, когда ключ передан **переменной окружения**: LiveQX не может сам заменить её значение. Задайте новое значение сами и перешифруйте секреты.

## Сброс

Сброс нужен, если ключ **потерян**. Он стирает все секреты, зашифрованные прежним ключом (пароли LDAP, SMTP и сетевых шар, секрет сессий), и создаёт новый ключ. Учётные записи пользователей и их пароли сохраняются.

```
sudo systemctl stop liveqx
sudo liveqx --config /etc/liveqx/config.json --reset-master-key --confirm-reset
sudo systemctl start liveqx
```

После сброса заново введите пароли LDAP, SMTP и сетевых шар. Все пользователи выйдут из системы.

## Резервная копия ключа

**Копируйте ключ отдельно от данных.** Резервная копия данных без ключа нечитаема, а ключ рядом с данными ничего не защищает.

- Файл: сохраните `/etc/liveqx/master.key` в надёжном месте, не там, где лежит копия данных.
- Парольная фраза: сохраните файл ключа и **запомните или надёжно запишите фразу**. Без неё ключ не открыть.
- Учётные данные systemd: ключ нигде больше не хранится, поэтому сохраните расшифрованную копию: `sudo systemd-creds decrypt /etc/credstore.encrypted/liveqx_master_key - | base64`. Без неё при поломке сервера или TPM ключ будет потерян.

## Чего это не защищает

Если злоумышленник получил права администратора операционной системы на **работающем** сервере, он может достать ключ из памяти процесса. Защита рассчитана на кражу диска, образа машины или резервной копии, а не на это.
