# Выходы — общее

Выход — это способ, которым канал отдаёт готовый поток наружу. Без выходов канал работает, но смотреть его некому.

У одного канала может быть несколько выходов разных типов. Канал **кодирует видео один раз**, а каждый выход лишь доставляет готовый поток по-своему. Поэтому добавление выхода почти не нагружает сервер — это не то же самое, что добавление нового канала.

## Типы выходов

### SRT

LiveQX открывает порт и **ждёт подключения зрителя** (режим «слушающий сервер»). Приёмник (VLC, ffplay, другой сервер, декодер) подключается к адресу `srt://адрес-сервера:порт`.

**Когда выбирать:** надёжная доставка по сети с потерями, контрибуция на другой сервер, проверка потока в VLC.

Особенности: SRT-выход обслуживает одного подключённого зрителя за раз.

### Multicast

MPEG-TS по UDP в группу multicast. Один поток принимают сразу многие получатели без роста нагрузки на сервер.

**Когда выбирать:** корпоративная сеть, гостиничное IPTV, внутренние экраны, строгие приёмники и middleware (задаются Service ID, TSID и другие параметры MPEG-TS на вкладке «Конфигурация»).

**Минусы:** работает только в сетях, где включён multicast; через интернет не ходит. Для multicast обычно требуется постоянный битрейт (CBR).

### RTMP (отправка на внешнюю площадку)

LiveQX сам подключается к внешнему серверу и отправляет туда поток: YouTube, VK Видео, Twitch, Restream или собственный RTMP-сервер. Принимать RTMP-потоки LiveQX не умеет — только отправлять.

Адрес вида `rtmp://…` или `rtmps://…` (с шифрованием). Если соединение рвётся, LiveQX переподключается сам, увеличивая паузу между попытками от 1 секунды до 1 минуты.

### HLS

LiveQX нарезает поток на короткие сегменты `.ts` и записывает их вместе с плейлистом `stream.m3u8` в **каталог на сервере**. Раздаёт эти файлы зрителям отдельный веб-сервер (например, nginx) или CDN — собственного HTTP-сервера для HLS в LiveQX нет.

**Когда выбирать:** показ в браузере и мобильных приложениях.

**Минусы:** задержка в десятки секунд — так устроен формат. Сегмент по умолчанию 6 секунд, в плейлисте 5 сегментов.

### NDI

Передача студийного качества по локальной сети в микшеры и мониторы (vMix, OBS, NDI Studio Monitor). Работает только если на сервере есть библиотека NDI. Выход NDI поддерживается сервером, но в форме добавления выхода в веб-интерфейсе его пока нет: он настраивается через REST API или файл конфигурации канала. Подробнее: [Добавить выход](ADD_OUTPUT.md).

## Чего в LiveQX нет

RTSP-выхода нет: отдавать RTSP-поток наружу LiveQX не может. RTSP поддерживается только как **источник** (см. [Live-источники](LIVE_INPUT_USER.md)).

## Что выбрать

| Зачем нужен поток | Тип |
|---|---|
| Проверить картинку, отдать одному приёмнику | SRT |
| Экраны в офисе, гостинице, ТЦ | Multicast |
| Сайт, мобильное приложение | HLS (+ веб-сервер) |
| YouTube, VK, Twitch и другие платформы | RTMP |
| Студийный микшер | NDI |

## Состояние выхода

На вкладке **Выходы** для каждого выхода видно: подключён ли он, битрейт, сколько отправлено байтов и пакетов, заполнение очереди, потерянные пакеты и кадры, число переподключений, RTT (для SRT).

Если очередь выхода переполняется (приёмник не успевает забирать данные), пакеты отбрасываются и растут счётчики потерь — это сигнал о проблеме на стороне сети или приёмника. Размер очереди задаётся в форме выхода (по умолчанию 4 МБ).

Выход можно временно отключить переключателем **Включён**, не удаляя его.
