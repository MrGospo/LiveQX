# Источник контента

Источник контента — это правило, по которому канал получает свой плейлист. Задаётся при создании канала или позже на вкладке **Конфигурация** → блок **Источник контента**.

Доступно три режима.

## Выкл (ручной плейлист)

Канал не читает файлы из папки. Плейлист заполняет оператор вручную — см. [Плейлист канала](PLAYLIST_USER.md). Этот режим подходит и каналу, который играет только [live-источники](LIVE_INPUT_USER.md).

## Passthrough

Канал следит за указанной **папкой** и играет файлы прямо из неё, без копирования.

- Новые файлы появляются в плейлисте быстро.
- Если папка пропадёт (например, оборвётся сетевая шара), канал потеряет доступ к контенту.

Подходит для локальных папок на самом сервере.

## Кэш

Фоновая служба канала следит за папкой (**источником**, например сетевой шарой), копирует файлы в **локальный кэш**, а канал играет из кэша.

- Канал устойчив к обрывам сети: пока шара недоступна, он продолжает играть то, что уже в кэше.
- Нужно место на диске сервера под копии файлов.
- Путь кэша можно не указывать — тогда используется подпапка `cache` в каталоге канала.

Подходит для сетевых шар (CIFS/NFS).

## Что общего у Passthrough и «Кэша»

### Как попадают файлы

- Плейлист формируется автоматически из **файлов, лежащих непосредственно в указанной папке**. Вложенные папки не просматриваются.
- При первом запуске файлы добавляются в алфавитном порядке по имени. Чтобы задать нужный порядок, начните имена с номеров: `01_intro.mp4`, `02_lobby.jpg`, `03_promo.mp4`.
- Файлы, появившиеся позже, добавляются **в конец** плейлиста.
- Файл, удалённый из папки, исчезает из плейлиста; если он сейчас в эфире, его досматривают до конца.

### Какие файлы подходят

Только по расширению:

- **Фотографии:** `.jpg`, `.jpeg`, `.png`, `.bmp`, `.webp`.
- **Видео:** `.mp4`, `.avi`, `.mkv`, `.mov`, `.ts`.

Остальные файлы (`.tmp`, `.part`, `.upload`, документы и т. д.) игнорируются без ошибок.

### Защита от недокопированных файлов

Новый файл попадает в плейлист не сразу: сервер ждёт, пока его размер и время изменения перестанут меняться между двумя проверками. Поэтому безопасно копировать файлы в папку прямо во время работы канала.

### Период проверки

Папка проверяется каждые **2 секунды** (значение по умолчанию). Если папка недоступна, интервал постепенно увеличивается до 30 секунд, а как только доступ вернётся, проверка снова идёт с обычной частотой.

## Как настроить папку на сетевой шаре

1. Администратор подключает шару в **Настройки → Хранилища** — см. [Сетевые шары](MOUNTS_USER.md). Она появляется на сервере в `/mnt/liveqx/…`.
2. В настройках источника контента выберите режим **Кэш** и укажите папку на шаре, например `/mnt/liveqx/media/promo`. Выбирать папку кнопкой обзора может администратор; остальные вводят путь вручную.

## Вкладка «Наблюдатель»

Показывает состояние службы синхронизации: режим, источник, кэш, число файлов и размер кэша, интервал сканирования, время последнего успешного скана, число недоступных обращений к шаре, ошибки копирования, файлы, ожидающие удаления, и файлы, пропущенные как слишком большие. Кнопка **Пересканировать** запускает проверку немедленно.

Если у канала источник не задан, вкладка сообщит, что наблюдатель отключён.

## Что выбрать

| Ситуация | Режим |
|---|---|
| 5–10 файлов, меняются редко, оператор управляет вручную | Выкл (ручной плейлист) |
| Контент лежит в локальной папке на сервере | Passthrough |
| Контент готовит другая команда на сетевой шаре | Кэш |
| Канал играет только live-источники | Выкл |
